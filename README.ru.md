# NeuraFour

[![CI](https://github.com/Vinbe0/neurafour/actions/workflows/ci.yml/badge.svg)](https://github.com/Vinbe0/neurafour/actions/workflows/ci.yml) [![Deploy](https://github.com/Vinbe0/neurafour/actions/workflows/deploy.yml/badge.svg)](https://github.com/Vinbe0/neurafour/actions/workflows/deploy.yml)

**«Четыре в ряд» с поисковым движком, который просчитывает 14+ ходов вперёд, онлайн-игрой в реальном времени и коучем, который разбирает вашу партию.**

**▶ Играть: [vinbe0.github.io/neurafour](https://vinbe0.github.io/neurafour/)**  ·  [English version](README.md)

![Игровой экран NeuraFour](docs/screenshot.png)

## Возможности

- **ИИ-соперник, четыре уровня.** «Легко» смотрит на 2 хода вперёд (иногда ходит случайно), «Средне» на 4, «Сложно» на 6, а «Эксперт» ищет так глубоко, как успеет за 750 мс, обычно на 14+ ходов. Поиск работает в Web Worker, поэтому страница не зависает, пока ИИ думает.
- **Онлайн-мультиплеер.** Создайте комнату, отправьте другу ссылку-приглашение и играйте в реальном времени через WebSocket, с чатом и реваншем. Если перезагрузить страницу, вы вернётесь в ту же партию.
- **ИИ-коуч.** После партии каждый ход получает оценку (идеально / отлично / хорошо / неточность / грубая ошибка) по сравнению с лучшим ходом движка. Коуч показывает упущенные победы, пропущенные защиты и ходы, которые отдали победу сопернику.
- **Аккаунты и рейтинг.** Вход через Supabase, глобальный рейтинг и рейтинг по городам, история матчей. Очки считает база данных, а не браузер ([подробнее](#безопасность-рейтинга)). Без сети всё работает на локальном кэше в localStorage.
- **Прогресс.** Уровни, CyberPoints, магазин скинов и прототип PRO-тарифа.
- **Интерфейс на английском и русском.** Полноценная система переводов с переключателем в шапке. Выбор запоминается, а по умолчанию берётся язык браузера.
- **Удобное управление.** Клавиатура (`1`–`7` или `←`/`→` + `Enter`, `U` — отмена хода), отмена хода, выбор, кто ходит первым против ИИ, список ходов и полупрозрачная подсказка, куда упадёт фишка.
- Тёмная и светлая темы (выбор запоминается), адаптивная вёрстка вплоть до телефона, звуки, подсветка победной линии и уведомления внутри приложения. Анимации сокращаются, если в системе включено «уменьшить движение».

## Как устроен ИИ

[`src/engine.ts`](src/engine.ts) — поиск по дереву игры, оптимизированный по скорости:

1. **Negamax с альфа-бета отсечением.** Сначала проверяются центральные колонки (`3, 2, 4, 1, 5, 0, 6`), поэтому отсечение отбрасывает гораздо больше ветвей. Более быстрая победа оценивается выше, чем более поздняя.
2. **Таблица транспозиций.** В одну и ту же позицию часто приходят разными порядками ходов. Каждая позиция получает 53-битный **хеш Зобриста**, а её оценка и лучший ход сохраняются в таблице, чтобы не считать их повторно.
3. **Итеративное углубление с лимитом времени.** «Эксперт» ищет на 1 ход вперёд, потом на 2, на 3 и так далее, пока не закончатся 750 мс, и играет лучший ход из самого глубокого завершённого поиска. Благодаря таблице каждый следующий круг намного быстрее предыдущего.
4. **Инкрементальная оценка.** Доска хранится в типизированных массивах, которые меняются на месте. После хода пересчитываются только линии из четырёх клеток, проходящие через эту клетку (не больше 13), а не вся доска.

На пустой доске движок просчитывает 12 ходов примерно за 60 мс и 14 ходов примерно за 250 мс. Тесты сверяют его с обычным минимаксом: на сотнях случайных позиций оценки совпадают на каждой глубине.

[`src/ai.ts`](src/ai.ts) добавляет тактические проверки (взять победу, закрыть угрозу) и **ИИ-коуча**, который сравнивает каждый ваш ход с рекомендацией движка и оценкой до и после хода. Поиск выполняется в **Web Worker** ([`src/ai.worker.ts`](src/ai.worker.ts)), а если воркеры недоступны, то в основном потоке.

## Архитектура мультиплеера

```
Браузер ──WebSocket──▶ Сервер на Node (TypeScript, Express + ws)
                        • комнаты с кодом из 5 символов
                        • сервер хранит доску, список ходов и очередь хода
                        • проверяет каждый ход тем же модулем правил, что и браузер
                        • 30 секунд держит место отключившегося игрока, чтобы он мог вернуться
```

Сервер ([`server/app.ts`](server/app.ts)) — единственный источник правды и защищён от злоупотреблений: принимает подключения только с разрешённых сайтов, ограничивает число подключений с одного адреса, размер и частоту сообщений, общее число комнат, регулярно пингует соединения и отключает «мёртвые», а принять реванш может только *другой* игрок. Он отклоняет ходы не в свою очередь, в заполненные или несуществующие колонки и после конца партии, поэтому изменённый клиент не может жульничать. Сервер использует тот же [`src/rules.ts`](src/rules.ts), что и браузер, и ограничивает длину имён и сообщений чата. Каждый игрок получает секретный токен: после перезагрузки страницы браузер с его помощью возвращает себе место и получает ходы и чат. `GET /health` показывает число активных комнат.

## Технологии

React 19 · TypeScript · Vite · Web Workers · Node.js · Express · `ws` · Supabase (Postgres, Auth, row-level security, PL/pgSQL) · Vitest · Playwright · GitHub Actions

## Тесты

| Команда | Что проверяет |
| --- | --- |
| `npm test` | 68 модульных тестов (Vitest): правила, движок против эталонного минимакса, сила ИИ в партиях против самого себя, модуль состояния игры, ИИ-коуч и мультиплеер-сервер (включая его ограничения) с настоящими WebSocket-клиентами |
| `npm run test:e2e` | Playwright в Chromium: игра против ИИ с отменой хода, партия только с клавиатуры, разбор коуча, язык и тема, все диалоги, онлайн-партия двух браузеров в разных часовых поясах (в том числе с перезагрузкой страницы посреди игры) и проверки доступности WCAG 2.1 AA через axe-core на каждом экране |
| `npm run test:db` | Схема Supabase и миграция с подсчётом очков на настоящей базе Postgres, включая попытки жульничать |

[CI](.github/workflows/ci.yml) запускает все три набора на каждый pull request, а деплой ещё раз прогоняет модульные тесты перед публикацией.

## Локальный запуск

```bash
npm install
npm run dev        # клиент Vite + WebSocket-сервер на :5001 (Node 22.18+)
```

**Онлайн-игра на своём компьютере:** откройте http://localhost:5173 в двух окнах браузера. В одном выберите **Онлайн 1v1 → Создать комнату** и скопируйте ссылку-приглашение. Откройте ссылку во втором окне и нажмите **Подключиться**.

**Игра с кем-то в той же Wi-Fi-сети:** запустите `npm run dev:lan` и отправьте адрес из строки `Network:` (например, `http://192.168.1.20:5173`). Браузер собеседника подключится к мультиплеер-серверу на вашем компьютере. macOS может спросить, разрешить ли входящие подключения для Node.

Необязательные настройки в `.env.local`:

```env
VITE_SUPABASE_URL=...
VITE_SUPABASE_PUBLISHABLE_KEY=...
VITE_WS_URL=wss://your-server.example.com   # по умолчанию ws://<host>:5001
```

Чтобы включить настоящий рейтинг, выполните [`supabase/schema.sql`](supabase/schema.sql) в SQL-редакторе Supabase, а затем по порядку все файлы из [`supabase/migrations/`](supabase/migrations/).

### Безопасность рейтинга

Вошедшие игроки не могут записать себе очки сами. Напрямую они меняют только имя, город и аватар; очки и статистика меняются только через функции базы данных ([миграция](supabase/migrations/20261026000000_server_side_scoring.sql)):

- `record_match` сама считает очки за результат, не засчитывает локальные партии вдвоём, принимает не больше одного результата в 20 секунд и не больше 600 очков в сутки
- `spend_points` списывает очки за подсказки и скины по ценам, заданным на сервере, и не даёт уйти в минус
- `activate_pro` включает (бесплатный, демонстрационный) PRO-тариф

Результат партии всё ещё сообщает браузер, потому что сервер не переигрывает партии против ИИ. Поэтому эти ограничения не делают жульничество невозможным, а ограничивают, сколько можно на нём выиграть.

`npm run test:db` проверяет всё это на настоящей базе Postgres (`DATABASE_URL` должен указывать на сервер, где можно создать временную базу). CI запускает эту проверку на каждый pull request.

## Деплой

- **Фронтенд:** GitHub Pages, публикуется workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) при каждом push в `main`. Значения `VITE_*` берутся из переменных Actions репозитория.
- **Мультиплеер-сервер:** Render, описан в [`render.yaml`](render.yaml) (бесплатный веб-сервис, проверка здоровья по `/health`). `ALLOWED_ORIGINS` задаёт сайты, которым можно подключаться (сайт на GitHub Pages), а `TRUST_PROXY=true` позволяет ограничениям по адресу видеть настоящий адрес игрока за прокси Render.
